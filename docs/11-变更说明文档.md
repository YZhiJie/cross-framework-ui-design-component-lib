# 11 - 变更说明（迭代二：图标自定义 / Switch 双态文本 / 主题 token）

> 版本目标：`0.1.0` → `0.2.0`（minor，全部为增量变更，无破坏性修改）
> 变更范围：`@xui-design/core`、`@xui-design/shared`、`@xui-design/vue`、`@xui-design/react`、`@xui-design/styles`（changeset 统一联动发布）
> 设计参照：antd / element-plus 的图标插槽、Switch 文本子元素、CSS Design Token 主题定制规范

## 一、新增属性清单

### Switch：`checkedText` / `uncheckedText`

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `checkedText` | `string` | `—`（未提供） | 开启态展示文本，位于轨道内滑块左侧 |
| `uncheckedText` | `string` | `—`（未提供） | 关闭态展示文本，位于轨道内滑块右侧 |

- 二者均为可选，**未提供时组件与旧版渲染完全一致**（纯开关 / 仅图标模式，轨道宽度、滑块位移逐像素不变）
- 任一属性提供**非空字符串**时，根元素追加 `xui-switch--has-text` 修饰类，轨道自动加宽（md 56px / sm 44px）并同步调整滑块位移
- 文本与开关的布局通过绝对定位锚定（`left` / `right: 8px`），滑块位移经几何验算（`translateX = 轨道宽 − 2×padding − 滑块宽`），无重叠、无溢出

## 二、新增图标插槽 / 回调清单

所有图标均通过「Vue 具名插槽 / React render 回调」传入自定义图标组件（第三方图标库组件或任意 `ReactNode` / VNode），未传入时渲染内置图标，行为与旧版一致。属性命名延续现有 `renderXxx` / `#xxx` 规范，与既有 API 无冲突。

| 组件 | Vue 插槽 | React 回调 | 替换的内置图标 | 本批新增 |
|------|----------|------------|----------------|----------|
| Button | `#icon` / `#loadingIcon` | `renderIcon` / `renderLoadingIcon` | 前置图标 / 加载 Spinner | —（已有） |
| Tag | `#closeIcon` | `renderCloseIcon` | 关闭 × | ✅ |
| Modal | `#closeIcon` | `renderCloseIcon` | 右上角关闭 × | ✅ |
| Alert | `#icon` / `#closeIcon` | `renderIcon` / `renderCloseIcon` | 语义图标 / 关闭 × | ✅ closeIcon |
| Input | `#clearIcon` | `renderClearIcon` | 可清空清除 × | —（已有） |
| Select | `#clearIcon` / `#suffixIcon` | `renderClearIcon` / `renderSuffixIcon` | 清除 × / 下拉箭头 | ✅ |
| Switch | `#loadingIcon` | `renderLoadingIcon` | 加载 Spinner | —（已有） |
| DatePicker | `#calendarIcon` / `#clearIcon` / `#prevIcon` / `#nextIcon` | `renderCalendarIcon` / `renderClearIcon` / `renderPrevIcon` / `renderNextIcon` | 日历 / 清除 / 月份翻页 | ✅ |
| InputNumber | `#upIcon` / `#downIcon` | `renderUpIcon` / `renderDownIcon` | 步进箭头 | ✅ |
| Pagination | `#prevIcon` / `#nextIcon` | `renderPrevIcon` / `renderNextIcon` | 翻页箭头 | ✅ |
| Checkbox | `#checkIcon` / `#indeterminateIcon` | `renderCheckIcon` / `renderIndeterminateIcon` | 选中勾 / 半选横线 | ✅ |
| Avatar | `#icon` | `renderIcon` | 占位用户图标 | ✅ |
| Table | `#sortIcon`（作用域 `order`） | `renderSortIcon({ order })` | 排序箭头 | ✅ |
| Empty | `#image` | `renderImage` | 空态插画 | —（已有） |

Table 排序图标为**作用域插槽 / 带参回调**，可按升序 / 降序分别定制：

```vue
<!-- Vue -->
<xui-table :columns="columns" :data-source="rows">
  <template #sortIcon="{ order }">
    <my-arrow-icon :direction="order" />
  </template>
</xui-table>
```

```tsx
// React
<Table
  columns={columns}
  dataSource={rows}
  renderSortIcon={({ order }) => <MyArrowIcon direction={order} />}
/>
```

### Message：`icon` 选项

命令式 `message.open()` 的 `MessageOptions` 新增 `icon?: string`（内层 SVG 标记字符串，与 `@xui-design/icons` 数据源同构），优先级高于按 `type` 内置的语义图标；`key` 更新路径下未传 `icon` 时保留原值：

```ts
import { message } from '@xui-design/vue'; // 或 '@xui-design/react'

message.open({
  type: 'success',
  content: '部署完成',
  icon: '<circle cx="12" cy="12" r="10"/><path d="M8 12l3 3 5-6"/>',
});
```

## 三、新增主题 API（全局 / 组件级定制）

`@xui-design/shared` 新增，`@xui-design/vue` / `@xui-design/react` 均 re-export，SSR（无 `document`）环境静默降级不抛错：

| API | 签名 | 说明 |
|-----|------|------|
| `setThemeTokens` | `(tokens: ThemeTokens) => void` | 全局覆盖设计 token：将 `--xui-*` CSS 变量写入 `<html style>`，全站生效，优先级高于 `data-theme` 预设值；仅接受 `--` 前缀键 + string 值（非法项**静默忽略**），重复调用按键合并覆盖 |
| `clearThemeTokens` | `() => void` | 精确清除 `setThemeTokens` 写入过的变量（不触碰其它内联样式），恢复预设主题 |
| `ThemeTokens` | `type ThemeTokens = Record<string, string>` | token 键值类型 |

### 使用方式

```ts
// 全局主题定制：一键换主色 / 圆角 / 阴影
import { setThemeTokens, clearThemeTokens } from '@xui-design/vue'; // 或 '@xui-design/react'

setThemeTokens({
  '--xui-color-primary': '#7c3aed',
  '--xui-color-primary-hover': '#8b5cf6',
  '--xui-radius-md': '10px',
});

clearThemeTokens(); // 恢复预设主题
```

```vue
<!-- 组件级定制：仅作用于该组件子树（优化批次 3 的 style 透传天然支持） -->
<xui-button :style="{ '--xui-color-primary': '#0ea5e9' }">天蓝按钮</xui-button>
<xui-switch :style="{ '--xui-color-primary': '#0ea5e9' }" />
```

```tsx
// React 组件级定制
<Button style={{ '--xui-color-primary': '#0ea5e9' }}>天蓝按钮</Button>;
<Switch style={{ '--xui-color-primary': '#0ea5e9' }} />;
```

常用可覆盖 token：`--xui-color-primary(-hover/-active)`、`--xui-color-success/warning/danger/info`、`--xui-color-text(-secondary)`、`--xui-color-border/bg*`、`--xui-radius-sm/md/lg`、`--xui-shadow-sm/md/lg` 及各组件局部变量（如 `--xui-table-row-height`）。

文档站（apps/docs）同步新增 `/theme` 主题定制指南页：三层机制说明 + 全局明暗切换 / 全局品牌色 / 组件级覆盖三个双端可交互 demo + 运行时 API 表格，侧边栏「开始」分组提供入口。

## 四、边界场景处理

| 场景 | 行为 |
|------|------|
| Switch 超长文本 | `max-width` 截断 + `text-overflow: ellipsis`，并携带 `title` 悬停提示完整内容 |
| Switch 空串文本 | `''` 视为未提供，不触发 `has-text` 加宽（`Boolean('')` 过滤） |
| Switch 仅提供单侧文本 | 仅渲染提供的侧；对侧保持纯开关视觉 |
| 图标插槽 / 回调未传 | 渲染内置图标，节点结构与旧版一致（条件渲染场景不产生多余节点） |
| 自定义图标过大 | 图标容器尺寸由组件控制（`1em` 基准 + flex 居中），建议自定义图标遵循 `1em` 视口规范 |
| `setThemeTokens` 非法输入 | 非 `--` 前缀键、非 string 值静默忽略（不抛错、不污染 `<html style>`） |
| `setThemeTokens` 重复调用 | 同键覆盖、异键合并，已写入键名记录在案供 `clearThemeTokens` 精确回收 |
| `clearThemeTokens` 未写入时调用 | no-op，不报错 |
| Message icon 为非法 SVG | 交由浏览器 innerHTML 解析（同 `v-html` 语义），不影响消息本体渲染 |

## 五、无障碍（WCAG 2.1 AA）

- **装饰性图标隐藏**：双端全部内置图标 `<svg>` 统一携带 `aria-hidden="true"`，读屏不播报冗余图标语义
- **自定义图标建议**：有语义的第三方图标请自带 `role="img"` + `aria-label`；装饰性图标自带 `aria-hidden="true"`
- **Switch 双态文本**：文本节点 `aria-hidden="true"`——开关状态由 `role="switch"` + `aria-checked` 传达，避免读屏重复播报"开 已开启"
- **键盘操作不受影响**：Switch 空格 / 回车切换、Focus 边框环（`:focus-visible`）、Tab 焦点顺序均保持原有行为；Table `aria-sort`、Modal 焦点陷阱等既有 a11y 能力不变

## 八、多浏览器兼容性说明

本轮新增能力全部基于标准 Web 特性实现，无浏览器特定 API：

- CSS 变量（`--xui-*` + `var()`）：Chrome 49+ / Firefox 31+ / Safari 9.1+ / Edge 79+
- `text-overflow: ellipsis`、`max-width`：全浏览器基线支持
- SVG `aria-hidden` / `role="switch"` / `aria-checked`：全部目标浏览器支持
- 运行时仅依赖 `document.documentElement.style.setProperty/removeProperty`（IE11+ 语义）

**实测环境限制**：本地 CI 环境仅能对 Chrome（Chromium 内核）进行自动化实测；Firefox / Safari / Edge 最新 3 个版本建议通过 Playwright 矩阵在真实内核上回归，参考脚本：

```bash
npx playwright test --browser=firefox --browser=webkit --browser=chromium
```

（Playwright 的 webkit / chromium 引擎分别对应 Safari / Edge 同源内核，可覆盖四大引擎的最新 3 个大版本。）

## 九、注意事项

1. **升级即生效**：`pnpm add @xui-design/vue@0.2` 或 `@xui-design/react@0.2` 后无需任何迁移动作；如需灰度，可仅升级适配层，core / shared / styles 由 pnpm workspace 解析
2. **样式单一来源**：组件样式统一由 `@xui-design/styles` 输出，请勿在业务侧覆写 `.xui-switch__text` 等内部类名；定制请走本批的 CSS 变量体系
3. **token 作用域**：`setThemeTokens` 写在 `<html>` 上是全站全局；组件级定制务必通过组件 `style` 透传（仅子树生效），二者叠加时组件级优先
4. **`clearThemeTokens` 只回收自己写入的键**：业务侧手工写入 `<html style>` 的其它变量不受影响，反之亦然
5. **图标尺寸约定**：内置图标以 `stroke="currentColor"` 继承文字色、`1em` 视口随字号缩放；自定义图标建议保持该约定以获得一致的响应式尺寸与暗色主题适配
6. **Message.icon 为高级用法**：普通语义场景请继续使用 `type` 内置图标；`icon` 传入的 SVG 标记由调用方保证内容可信（同 `v-html` / `dangerouslySetInnerHTML` 风险模型，勿拼接用户输入）

## 十、浮层体验增强（Tooltip / Popconfirm / Select）

### 10.1 Select / Tooltip / Popconfirm 视口避让

浮层打开时自动测量触发器与浮层矩形，经 `@xui-design/shared` 新增的纯逻辑 `resolveFloatingPosition` 计算最终方位，Vue / React 双端同构接入：

- **flip（翻转）**：首选方位在视口内放不下且对侧空间更充足时翻转到对侧；两侧都不足时保持首选（避免无意义抖动）。Select 仅消费 flip 结果：下方空间不足向上展开，根元素加 `is-drop-up`，面板锚定触发器上方 4px；Tooltip / Popconfirm 支持四方位翻转，`is-top/bottom/left/right` 类名随实际方位更新，箭头方位同步跟随
- **shift（钳制）**：Tooltip / Popconfirm 交叉轴居中对齐后若超出视口边缘，向安全区内钳制（距边缘 ≥8px），通过 `margin-left` / `margin-top` 叠加，不破坏既有 CSS 包裹定位模型
- **实时重算**：浮层展示期间监听页面滚动（捕获阶段，覆盖任意可滚动祖先）与窗口 resize，rAF 合并后重新测量；关闭 / 卸载时解绑，无监听泄漏
- **零契约变更**：`placement` prop 语义仍为「首选方位」，翻转是内部行为；SSR 与无布局环境（jsdom 零尺寸矩形）下降级为不翻转、不偏移，既有测试与渲染快照不受影响

新增 9 个纯逻辑单例（`@xui-design/shared/floating`）+ 双端各 3 个组件级避让测试（桩接 `getBoundingClientRect` 模拟贴边场景）。

### 10.2 Popconfirm 小三角衔接修复

修复 `left` / `right`（窄面板下尤为明显）方位箭头与气泡边框之间出现缝隙、箭头呈漂浮独立菱形的问题：箭头改为双菱形结构——外层菱形使用气泡边框色、内层菱形（`inset: 1px`）使用气泡背景色，四方位定位与跟随类名不变，旋转后边缘与面板边框无缝衔接。

### 10.3 已知限制

- 避让基于浏览器可视视口（`innerWidth/innerHeight`），不识别 `overflow: hidden` 祖先造成的局部裁剪；浮层仍为非 portal 的 CSS 包裹定位，该裁剪场景需业务侧避免
- 翻转测量发生在浮层首帧按首选方位布局之后（rAF），极端慢帧下可能有一次首选方位的闪烁

### 10.4 附：Tooltip / Popconfirm stretch 布局错位修复（上一补丁）

气泡从相对包裹根定位改为锚定 `.xui-tooltip__trigger` / `.xui-popconfirm__trigger`（始终贴合触发器的 inline-block 容器），修复触发器作为 flex / grid 拉伸项时包裹根被拉高拉宽导致气泡偏移的问题；气泡内点击事件阻断冒泡，避免点击正文误触发开合。

### 10.5 附：Button danger 语义 token 修复（主题文档配套）

`.xui-button--danger` 背景 / 边框由硬编码 `#dc2626` 改为 `var(--xui-color-danger, #dc2626)`：此前暗色主题（`[data-theme='dark']` 已定义 `--xui-color-danger: #f87171`）与组件级 token 覆盖对 danger 按钮均不生效；hover / active 深色梯度暂无对应 token，保持硬编码。
