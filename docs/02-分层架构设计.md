# 02 - 分层架构设计

## 架构总览

采用**四层分层架构**，自底向上依次为：纯逻辑核心层 → 框架无关抽象层 → 框架适配层 → 消费应用层。

```
╔══════════════════════════════════════════════════════════╗
║                    消费应用层 (App)                        ║
║          Vue 3 项目 / React 17+ 项目                       ║
╚══════════════════════╤═══════════════════════════════════╝
                       │ import { Button } from '@xui/vue' | '@xui/react'
    ┌──────────────────┴──────────────────┐
    │           框架适配层 (Adapter)        │
    │  ┌────────────────┐ ┌──────────────┐ │
    │  │ @xui/vue       │ │ @xui/react   │ │
    │  │ Composition API │ │ Hooks + JSX  │ │
    │  │ defineComponent │ │ forwardRef   │ │
    │  └───────┬────────┘ └──────┬───────┘ │
    └──────────┼──────────────────┼────────┘
               │                  │
    ┌──────────┴──────────────────┴────────┐
    │       框架无关抽象层 (Abstract)        │
    │           @xui/core                    │
    │  Props 类型契约 / Events 契约           │
    │  ComponentSpec / SlotDef              │
    │  通用 hooks 接口 (createUseXxx)        │
    └──────────────────┬────────────────────┘
                       │
    ┌──────────────────┴────────────────────┐
    │         纯逻辑核心层 (Core)             │
    │           @xui/shared                  │
    │  状态管理 / 交互逻辑 / 校验逻辑          │
    │  工具函数 / 常量定义 / 类型定义          │
    │  (零框架依赖，纯 TypeScript)            │
    └────────────────────────────────────────┘
```

## 第一层：纯逻辑核心层（@xui/shared）

### 职责边界

| 职责 | 说明 | 示例 |
|------|------|------|
| 状态管理 | 组件内部状态的创建、读取、更新逻辑 | 弹窗 open/close、计数器、选中态 |
| 交互逻辑 | 用户交互行为处理（不涉及 DOM） | 点击防抖、拖拽数学计算、键盘导航逻辑 |
| 校验逻辑 | 表单校验规则、数据格式验证 | 必填校验、正则匹配、异步校验编排 |
| 工具函数 | 纯函数工具 | dateUtils、domUtils（不依赖框架）、formatUtils |
| 常量定义 | 枚举值、默认配置 | Size 枚举、Type 枚举、默认 Props |

### 设计原则

1. **零框架依赖**：核心层代码中不出现 `vue`、`react`、`@vue/reactivity` 等任何框架导入
2. **可测试性**：所有逻辑均为纯函数或可独立实例化的类/闭包，不依赖 DOM 环境即可单测
3. **状态外提**：状态管理使用自研轻量响应式（或直接使用 `EventTarget` + 闭包），不绑定框架响应式系统

### 核心代码示例

```typescript
// @xui/shared/src/components/button/use-button-logic.ts

export interface ButtonState {
  loading: boolean;
  disabled: boolean;
}

export interface ButtonLogicOptions {
  disabled?: boolean;
  loading?: boolean;
  onClick?: (e: MouseEvent) => void | Promise<void>;
}

/**
 * Button 核心逻辑 —— 框架无关
 * 不依赖 Vue ref 或 React useState，使用闭包 + 回调通知
 */
export function createButtonLogic(options: ButtonLogicOptions = {}) {
  let state: ButtonState = {
    loading: options.loading ?? false,
    disabled: options.disabled ?? false,
  };

  // 状态变更监听器，由适配层注册
  const listeners = new Set<(state: ButtonState) => void>();

  function subscribe(listener: (state: ButtonState) => void): () => void {
    listeners.add(listener);
    return () => listeners.delete(listener);
  }

  function getState(): ButtonState {
    return { ...state };
  }

  function setState(next: Partial<ButtonState>): void {
    state = { ...state, ...next };
    listeners.forEach((fn) => fn(getState()));
  }

  async function handleClick(e: MouseEvent): Promise<void> {
    if (state.disabled || state.loading) return;
    if (options.onClick) {
      setState({ loading: true });
      try {
        await options.onClick(e);
      } finally {
        setState({ loading: false });
      }
    }
  }

  function updateOptions(next: ButtonLogicOptions): void {
    options = { ...options, ...next };
    setState({
      loading: next.loading ?? state.loading,
      disabled: next.disabled ?? state.disabled,
    });
  }

  return {
    subscribe,
    getState,
    handleClick,
    updateOptions,
  };
}
```

### 状态通知机制

核心层使用 **观察者模式** 向适配层通知状态变更，而非直接操作框架响应式 API：

```
核心层                        适配层 (Vue/React)
┌──────────────┐             ┌──────────────────────┐
│ createButton │ subscribe() │ 适配层注册 listener    │
│ Logic()      │────────────>│ listener → ref.value  │ (Vue)
│              │             │ listener → setState()  │ (React)
│ setState()   │────notify──>│ 触发框架响应式更新      │
└──────────────┘             └──────────────────────┘
```

这种设计的优势：
- 核心层**不感知**框架响应式机制，完全解耦
- 适配层可以自由选择如何将状态同步到框架（Vue ref / React state / 甚至 MobX）
- 核心逻辑可以直接被 Node.js 环境测试，无需 jsdom

## 第二层：框架无关抽象层（@xui/core）

### 职责边界

| 职责 | 说明 |
|------|------|
| Props 契约定义 | 统一的 Props 类型定义，Vue/React 共用 |
| Events 契约定义 | 事件名、载荷类型、触发时机定义 |
| Slots/Children 定义 | 插槽映射规则、具名插槽约定 |
| ComponentSpec | 组件规格描述，包含 props schema + 事件 + 插槽 + 默认值 |
| 通用 Hook 接口 | 框架无关的 hook 工厂函数签名 |

### ComponentSpec 设计

```typescript
// @xui/core/src/spec.ts

import type { ButtonProps, ButtonEvents, ButtonSlots } from './components/button';

/**
 * 组件规格 —— 描述一个组件的完整契约
 * 这是 Vue 适配层和 React 适配层的"共享合同"
 */
export interface ComponentSpec<
  P extends Record<string, any>,
  E extends Record<string, any>,
  S extends Record<string, any>
> {
  /** 组件名，Vue 和 React 保持一致 */
  name: string;
  /** Props 类型定义（运行时 schema + 编译时 TS 类型） */
  props: PropsDefinition<P>;
  /** 事件定义 */
  events: EventsDefinition<E>;
  /** 插槽定义 */
  slots: SlotsDefinition<S>;
  /** 核心 hook 工厂（指向 @xui/shared 的逻辑） */
  useLogic: (options: P) => LogicInstance<P>;
}

interface PropsDefinition<P> {
  type: { [K in keyof P]: Constructor };
  defaults: Partial<P>;
  validator?: (props: P) => string[]; // 返回错误信息数组
}

interface EventsDefinition<E> {
  [eventName: string]: {
    payloadType?: string; // TS 类型引用名
    description: string;
  };
}

interface SlotsDefinition<S> {
  [slotName: string]: {
    props?: Record<string, any>; // 作用域插槽参数
    fallback?: string; // 默认内容
  };
}

interface LogicInstance<P> {
  subscribe: (fn: (state: any) => void) => () => void;
  getState: () => any;
  // ...核心逻辑暴露的方法
}
```

### Button 组件规格定义示例

```typescript
// @xui/core/src/components/button/spec.ts

import { createButtonLogic } from '@xui/shared';

export interface ButtonProps {
  type?: 'default' | 'primary' | 'danger' | 'link';
  size?: 'sm' | 'md' | 'lg';
  disabled?: boolean;
  loading?: boolean;
  block?: boolean;
}

export interface ButtonEvents {
  click: (e: MouseEvent) => void;
}

export interface ButtonSlots {
  default: {};
  icon: {};
  loadingIcon: {};
}

export const buttonSpec = {
  name: 'Button',
  props: {
    type: { type: String, default: 'default' },
    size: { type: String, default: 'md' },
    disabled: { type: Boolean, default: false },
    loading: { type: Boolean, default: false },
    block: { type: Boolean, default: false },
  },
  events: {
    click: { description: '点击按钮时触发' },
  },
  slots: {
    default: { description: '按钮内容' },
    icon: { description: '前置图标' },
    loadingIcon: { description: '加载态图标，默认为 Spinner' },
  },
  useLogic: (props: ButtonProps) => createButtonLogic({
    disabled: props.disabled,
    loading: props.loading,
    onClick: props.onClick, // 由适配层注入
  }),
} satisfies ComponentSpec<ButtonProps, ButtonEvents, ButtonSlots>;
```

### 抽象层与核心层的关系

```
@xui/core (抽象层)                @xui/shared (核心层)
┌──────────────────┐             ┌──────────────────────┐
│ ComponentSpec    │  import ──> │ createButtonLogic()  │
│ Props 契约        │             │ state 管理            │
│ Events 契约       │             │ 交互逻辑              │
│ Slots 契约       │             │ 校验逻辑              │
└──────────────────┘             └──────────────────────┘
```

抽象层是**纯类型 + 契约层**，几乎不包含运行时逻辑（运行时逻辑在核心层）。抽象层存在的意义：
- 为适配层提供统一的"合同"，避免 Vue/React 实现跑偏
- 为文档生成、Props 表格生成提供元数据
- 为测试提供 contract testing 的基准

## 第三层：Vue 适配层（@xui/vue）

### 职责边界

| 职责 | 说明 |
|------|------|
| 框架桥接 | 将核心层状态同步到 Vue 响应式系统（ref/reactive） |
| 模板渲染 | 使用 Vue SFC `<template>` 编写组件 UI |
| Props 声明 | 将抽象层 Props 契约转换为 Vue defineProps |
| 事件声明 | 将抽象层 Events 契约转换为 Vue defineEmits |
| 插槽声明 | 将抽象层 Slots 契约转换为 Vue defineSlots / `<slot>` |
| v-model 适配 | 将抽象层的 value/onChange 映射为 Vue v-model 语法糖 |
| provide/inject | Vue 专属的跨组件通信 |

### Vue 适配层代码示例

```vue
<!-- @xui/vue/src/button/button.vue -->
<script setup lang="ts">
import { ref, watchEffect, useSlots } from 'vue';
import { buttonSpec, type ButtonProps } from '@xui/core';
import { SpinIcon } from '@xui/vue/icons';

// 1. Props —— 从抽象层契约声明
const props = withDefaults(defineProps<ButtonProps>(), {
  type: 'default',
  size: 'md',
  disabled: false,
  loading: false,
  block: false,
});

// 2. Events —— 从抽象层契约声明
const emit = defineEmits<{
  (e: 'click', event: MouseEvent): void;
}>();

// 3. 核心逻辑 —— 调用 @xui/shared 的工厂函数
const logic = buttonSpec.useLogic(props);

// 4. 状态桥接 —— 核心层状态 → Vue ref
const state = ref(logic.getState());
logic.subscribe((next) => {
  state.value = next;
});

// 5. Props 变更 → 同步到核心逻辑
watchEffect(() => {
  logic.updateOptions({
    disabled: props.disabled,
    loading: props.loading,
  });
});

// 6. 事件处理 —— 调用核心逻辑 + 向上 emit
function handleClick(e: MouseEvent) {
  logic.handleClick(e);
  emit('click', e);
}

const slots = useSlots();
</script>

<template>
  <button
    :class="[
      'xui-button',
      `xui-button--${props.type}`,
      `xui-button--${props.size}`,
      { 'is-disabled': state.disabled, 'is-loading': state.loading, 'is-block': props.block }
    ]"
    :disabled="state.disabled || state.loading"
    @click="handleClick"
  >
    <span v-if="slots.icon" class="xui-button__icon">
      <slot name="icon" />
    </span>
    <span v-if="state.loading" class="xui-button__loading-icon">
      <slot name="loadingIcon">
        <SpinIcon />
      </slot>
    </span>
    <span class="xui-button__content">
      <slot />
    </span>
  </button>
</template>
```

### Vue 适配层通信流程

```
用户点击
    │
    ▼
Vue 事件 @click
    │
    ▼
handleClick(e)           ← Vue 适配层方法
    │
    ├─> logic.handleClick(e)   ← 调用核心层逻辑
    │       │
    │       └─> setState({ loading: true })
    │               │
    │               └─> listeners.notify() → Vue ref 更新
    │                       │
    │                       └─> Vue 重新渲染 <button>
    │
    └─> emit('click', e)      ← 向父组件冒泡事件
```

## 第四层：React 适配层（@xui/react）

### 职责边界

| 职责 | 说明 |
|------|------|
| 框架桥接 | 将核心层状态同步到 React state（useSyncExternalStore） |
| JSX 渲染 | 使用 JSX 编写组件 UI，与 Vue 模板对齐 |
| Props 传递 | 将抽象层 Props 契约用作 React 组件 Props 类型 |
| 事件处理 | 将抽象层 Events 映射为 onXxx 回调 Props |
| Children/Render Props | 将抽象层 Slots 映射为 children / render props |
| ref 暴露 | React 19+: ref 作为普通 prop；React 17/18: forwardRef |
| Context | React 专属的跨组件通信 |

### React 适配层代码示例

React 19+ 原生支持 `ref` 作为普通 prop，无需 `forwardRef`。组件库以 React 19 写法为主，同时提供 17/18 兼容路径：

```tsx
// @xui/react/src/button/button.tsx — React 19+ 版本（主推荐）
import { useImperativeHandle, useEffect } from 'react';
import { useSyncExternalStore } from '../../hooks/use-sync-external-store';
import { buttonSpec, type ButtonProps } from '@xui/core';
import { SpinIcon } from '@xui/react/icons';
import { cn } from '../../utils/cn';

// 1. React Props —— 从抽象层类型 + 事件回调 + ref
export interface ButtonComponentProps extends ButtonProps {
  onClick?: (e: MouseEvent) => void;
  children?: React.ReactNode;
  // 插槽映射为 render props
  renderIcon?: () => React.ReactNode;
  renderLoadingIcon?: () => React.ReactNode;
  // React 19: ref 作为普通 prop
  ref?: React.Ref<ButtonRef>;
}

// 2. ref 暴露接口
export interface ButtonRef {
  focus: () => void;
  setLoading: (loading: boolean) => void;
}

// 3. 组件实现 —— 无需 forwardRef 包装
export function Button({ ref, ...props }: ButtonComponentProps) {
  // 核心逻辑实例
  const logic = buttonSpec.useLogic(props);

  // Props 变更同步
  useEffect(() => {
    logic.updateOptions({
      disabled: props.disabled,
      loading: props.loading,
    });
  }, [props.disabled, props.loading]);

  // 状态桥接 —— 核心层状态 → React (useSyncExternalStore)
  const state = useSyncExternalStore(
    logic.subscribe,
    logic.getState,
    logic.getState // SSR 快照
  );

  // ref 暴露（React 19 中 ref 是普通 prop，可直接使用）
  useImperativeHandle(ref, () => ({
    focus: () => { /* ... */ },
    setLoading: (loading: boolean) => logic.updateOptions({ loading }),
  }), []);

  // 事件处理
  const handleClick = (e: React.MouseEvent) => {
    logic.handleClick(e.nativeEvent);
    props.onClick?.(e.nativeEvent);
  };

  return (
    <button
      className={cn(
        'xui-button',
        `xui-button--${props.type}`,
        `xui-button--${props.size}`,
        {
          'is-disabled': state.disabled,
          'is-loading': state.loading,
          'is-block': props.block,
        }
      )}
      disabled={state.disabled || state.loading}
      onClick={handleClick}
    >
      {props.renderIcon && (
        <span className="xui-button__icon">{props.renderIcon()}</span>
      )}
      {state.loading && (
        <span className="xui-button__loading-icon">
          {props.renderLoadingIcon ? props.renderLoadingIcon() : <SpinIcon />}
        </span>
      )}
      <span className="xui-button__content">{props.children}</span>
    </button>
  );
}
```

React 17/18 兼容版本使用 `forwardRef`：

```tsx
// @xui/react/src/button/button-legacy.tsx — React 17/18 版本
import { forwardRef, useImperativeHandle } from 'react';
// ... 与上方逻辑一致，仅外层用 forwardRef 包装
export const Button = forwardRef<ButtonRef, ButtonComponentProps>(
  (props, ref) => { /* 同上实现 */ }
);
Button.displayName = 'Button';
```

运行时根据 React 版本选择导出路径（详见 [05-兼容性与质量保障](05-兼容性与质量保障.md#13-react-171819-差异处理)）。

### React 状态桥接关键点

```typescript
// 使用 React 18 的 useSyncExternalStore 实现核心层状态订阅
const state = useSyncExternalStore(
  logic.subscribe,        // 订阅函数
  logic.getState,         // 客户端快照
  logic.getState,         // SSR 快照
);
```

`useSyncExternalStore` 是 React 18+ 提供的外部状态订阅 API，天然适配核心层的观察者模式，避免了 `useState` + `useEffect` 的 tearing 问题。

## 层间通信机制总结

### 数据流向图

```
         ┌──────────────────────────────────────────────┐
         │              消费应用 (App)                    │
         └──────┬──────────────────────────────┬────────┘
                │ props                        │ events (↑)
         ╔══════╧════════════════════════════╧═════════╗
         ║              适配层 (Vue / React)              ║
         ║  ┌─────────────────────────────────────────┐  ║
         ║  │ 1. 接收 Props → 传递给核心层              │  ║
         ║  │ 2. 订阅核心层状态 → 同步到框架响应式       │  ║
         ║  │ 3. 调用核心层方法处理交互                 │  ║
         ║  │ 4. 核心层回调 → 转为框架事件向上冒泡      │  ║
         ║  │ 5. 渲染模板/JSX                          │  ║
         ║  └─────────────────────────────────────────┘  ║
         ╚══════┬──────────────────────────────┬─────────╝
                │ subscribe/updateOptions      │ handleClick 等
         ┌──────┴──────────────────────────────┴─────────┐
         │            抽象层 (@xui/core)                   │
         │  ComponentSpec 契约 / 类型定义                  │
         └──────┬──────────────────────────────┬─────────┘
                │ 调用逻辑工厂                   │ 返回状态/方法
         ┌──────┴──────────────────────────────┴─────────┐
         │            核心层 (@xui/shared)                  │
         │  createXxxLogic() → { subscribe, getState, ... }│
         └─────────────────────────────────────────────────┘
```

### 通信协议

| 方向 | 机制 | 数据格式 |
|------|------|----------|
| App → 适配层 | Props 传递 | 符合抽象层 Props 契约的对象 |
| 适配层 → 核心层 | `useLogic(options)` | 核心层工厂函数初始化 |
| 适配层 → 核心层 | `updateOptions(next)` | Props 变更同步 |
| 核心层 → 适配层 | `subscribe(listener)` | 回调函数，参数为 state 快照 |
| 适配层 → App | Events emit / callback | 符合抽象层 Events 契约 |
| 适配层 → App | Slots/Children | 符合抽象层 Slots 契约 |

### 关键设计约束

1. **核心层不可逆向调用适配层**：核心层不 import 任何适配层代码，不感知框架存在
2. **抽象层是唯一合同**：双端适配层的 Props/Events/Slots 必须与抽象层契约 100% 对齐
3. **状态只读原则**：适配层从核心层获取的 state 是只读快照，修改只能通过核心层暴露的方法
4. **事件不穿透**：核心层处理完逻辑后，由适配层负责向 App 发出事件，核心层不直接操作 DOM 或框架事件
