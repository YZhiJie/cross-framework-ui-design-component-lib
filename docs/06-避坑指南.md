## 痛点一：响应式系统差异

### 问题描述

Vue 使用基于 Proxy 的细粒度响应式追踪，React 使用基于 `useState` 的粗粒度状态快照。同一个状态变更在两端的更新粒度、批处理行为、时序完全不同，容易导致双端行为不一致。

### 根因分析

```
Vue 响应式                        React 状态更新
┌─────────────────────────┐      ┌──────────────────────────┐
│ ref(0) / reactive({})   │      │ const [v, setV] = useState(0) │
│                         │      │                          │
│ 修改 .value → Proxy 触发 │      │ setV(newV) → 调度重渲染    │
│ → 依赖该 ref 的 effect   │      │ → 函数组件重新执行        │
│   精确触发更新            │      │ → 整个组件函数重新运行     │
│                         │      │                          │
│ 默认同步更新             │      │ 默认异步批量更新           │
│ (nextTick 微任务)        │      │ (React 18 automatic batch) │
└─────────────────────────┘      └──────────────────────────┘
```

| 差异点 | Vue 3 | React 18 |
|--------|-------|----------|
| 更新粒度 | 细粒度（仅更新依赖该值的节点） | 粗粒度（整个组件函数重新执行） |
| 批处理 | 需手动 `nextTick` 等待 | automatic batching 自动合并 |
| 更新时序 | 修改后同步可读 | 修改后异步，当前渲染周期内仍为旧值 |
| 闭包陷阱 | 无（ref 可变） | 有（useState 返回值在闭包中固定） |

### 解决方案

**核心层使用观察者模式 + 快照机制，不依赖任何框架响应式系统**：

```typescript
// ✅ 正确：核心层返回不可变快照
function createCounter() {
  let count = 0;
  const listeners = new Set<(n: number) => void>();

  return {
    subscribe(fn: (n: number) => void) {
      listeners.add(fn);
      return () => listeners.delete(fn);
    },
    // 返回快照（不可变值），避免 Vue/React 引用同一对象
    getCount() { return count; },
    increment() {
      count++;
      listeners.forEach(fn => fn(count)); // 通知新值
    },
  };
}
```

**Vue 适配层桥接**：

```typescript
// Vue —— 使用 ref 包装核心层快照
function useCounter() {
  const logic = createCounter();
  const count = ref(logic.getCount());

  logic.subscribe((n) => {
    count.value = n; // 触发 Vue 响应式更新
  });

  return { count, increment: logic.increment };
}
```

**React 适配层桥接**：

```typescript
// React —— 使用 useSyncExternalStore 订阅核心层
function useCounter() {
  const logic = useRef(createCounter()).current;

  const count = useSyncExternalStore(
    logic.subscribe,
    logic.getCount,
    logic.getCount
  );

  return { count, increment: logic.increment };
}
```

### 闭包陷阱特别说明

```typescript
// ❌ React 闭包陷阱：count 在闭包中固定为 0
function BadComponent() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const timer = setInterval(() => {
      console.log(count); // 永远输出 0
      setCount(count + 1); // 永远设为 1
    }, 1000);
    return () => clearInterval(timer);
  }, []);
}

// ✅ 通过核心层避免：核心层自己管理状态，不依赖 React 闭包
function GoodComponent() {
  const { count, increment } = useCounter();
  useEffect(() => {
    const timer = setInterval(() => {
      increment(); // 核心层内部自增，不依赖 count 闭包值
    }, 1000);
    return () => clearInterval(timer);
  }, [increment]);
}
```

## 痛点二：虚拟 DOM 机制不同

### 问题描述

Vue 和 React 的虚拟 DOM diff 算法不同，`key` 的处理、列表更新、同级节点复用策略不一致，导致同一组件在双端渲染结果或性能表现不同。

### 根因分析

| 差异 | Vue 3 | React |
|------|-------|-------|
| diff 策略 | 双端对比（从头尾同时遍历） | 单端对比（仅从头遍历） |
| key 的作用 | 决定节点复用（同 key 复用，不同 key 重建） | 决定元素身份（同 key 复用状态） |
| 列表插入 | 支持中间插入（move 操作） | 不支持 move，只能删除+新建 |
| 静态提升 | 编译期静态节点提升，跳过 diff | 无编译优化，全量 diff |
| block tree | Block Tree 收集动态节点，精确 diff | 无 |

### 常见坑场景

#### 列表中间插入

```vue
<!-- Vue：列表中间插入节点，同 key 的节点会被移动（复用状态） -->
<template>
  <div v-for="item in items" :key="item.id">
    <input v-model="item.value" />
  </div>
</template>
```

```tsx
// React：列表中间插入节点，React 会销毁中间到末尾的节点再重建
// 导致 input 中的未保存数据丢失
{items.map(item => (
  <div key={item.id}>
    <input value={item.value} onChange={...} />
  </div>
))}
```

### 解决方案

**避免在组件内部依赖 diff 行为，将列表管理逻辑放在核心层**：

```typescript
// 核心层管理列表，提供稳定的 key 和操作 API
function createListManager<T extends { id: string }>(initial: T[]) {
  let items = [...initial];

  return {
    getItems: () => items,
    insert: (index: number, item: T) => {
      items = [...items.slice(0, index), item, ...items.slice(index)];
    },
    remove: (id: string) => {
      items = items.filter(i => i.id !== id);
    },
    move: (fromId: string, toId: string) => {
      // 核心层负责算好最终顺序，双端只负责渲染
      const fromIdx = items.findIndex(i => i.id === fromId);
      const toIdx = items.findIndex(i => i.id === toId);
      if (fromIdx < 0 || toIdx < 0) return;
      const [moved] = items.splice(fromIdx, 1);
      items.splice(toIdx, 0, moved);
    },
  };
}
```

**双端渲染统一使用 `key` 且保证 key 稳定唯一**：

```typescript
// ✅ Vue 和 React 都使用稳定的 id 作为 key
// 不要用数组 index 作为 key
{items.map(item => <ListItem key={item.id} item={item} />)}
```

## 痛点三：生命周期时序不一致

### 问题描述

同一个用户操作在 Vue 和 React 中触发生命周期的时序不同，导致双端行为在边界条件下不一致。

### 根因分析

```
操作：父组件 props 变更 + 子组件需要响应

Vue 时序：                          React 时序：
1. 父组件 re-render                  1. 父组件函数重新执行
2. 子组件 props 更新                  2. 子组件函数重新执行（新的 props）
3. 子组件 watch 触发 ─────────────>   3. useEffect 执行（无依赖变化限制）
4. 子组件 onUpdated                  4. useEffect cleanup → 新 effect
5. DOM 更新                          5. 浏览器绘制

关键差异：
- Vue 的 watch 是同步触发的（在 DOM 更新前）
- React 的 useEffect 是异步的（在浏览器绘制后）
- Vue onUpdated 在 DOM 更新后触发
- React 没有等价的 onUpdated，useEffect 兼任
```

### 常见坑场景

#### props 变化后立即读 DOM

```typescript
// ❌ React 中 useEffect 在绘制后执行，此时 DOM 已更新
//     但如果需要在绘制前操作 DOM，useEffect 太晚了
useEffect(() => {
  // 这里 DOM 已更新，但浏览器已绘制了旧 DOM（闪烁）
  inputRef.current.focus();
}, [value]);

// ✅ 使用 useLayoutEffect 在绘制前操作 DOM
useLayoutEffect(() => {
  inputRef.current.focus(); // 浏览器绘制前执行，无闪烁
}, [value]);
```

```vue
<!-- Vue：watch + flush:'post' 等效于 React useEffect -->
<script setup>
import { watch, nextTick } from 'vue';

// flush: 'pre' (默认) — DOM 更新前执行（类似 useLayoutEffect）
// flush: 'post' — DOM 更新后执行（类似 useEffect）
watch(() => props.value, (newVal) => {
  // 默认在 DOM 更新前执行
  nextTick(() => {
    // DOM 更新后执行
    inputRef.value?.focus();
  });
});
</script>
```

### 解决方案

**统一生命周期映射表**：

| 场景 | Vue | React | 说明 |
|------|-----|-------|------|
| DOM 更新前操作 | `watch(fn, cb, { flush: 'pre' })` | `useLayoutEffect` | 避免闪烁 |
| DOM 更新后操作 | `watch(fn, cb, { flush: 'post' })` 或 `onUpdated` | `useEffect` | 测量布局等 |
| 仅挂载时执行 | `onMounted` | `useEffect(() => {}, [])` | 初始化 |
| 仅卸载时执行 | `onBeforeUnmount` | `useEffect(() => cleanup, [])` | 清理 |

**核心层提供统一的 `useEffect` 抽象**：

```typescript
// @xui/shared/src/lifecycle.ts

export interface LifecycleAdapter {
  /** DOM 更新前执行（避免闪烁的场景） */
  onPreEffect: (fn: () => void | (() => void), deps: any[]) => void;
  /** DOM 更新后执行 */
  onPostEffect: (fn: () => void | (() => void), deps: any[]) => void;
  /** 仅挂载时执行 */
  onMount: (fn: () => void | (() => void)) => void;
  /** 仅卸载时执行 */
  onUnmount: (fn: () => void) => void;
}
```

Vue 适配层实现：

```typescript
import { watch, onMounted, onBeforeUnmount, nextTick } from 'vue';

const vueLifecycleAdapter: LifecycleAdapter = {
  onPreEffect(fn, deps) {
    const stop = watch(deps, () => fn(), { flush: 'pre' });
    onBeforeUnmount(stop);
  },
  onPostEffect(fn, deps) {
    const stop = watch(deps, async () => {
      await nextTick();
      fn();
    }, { flush: 'post' });
    onBeforeUnmount(stop);
  },
  onMount(fn) {
    const cleanup = ref<(() => void) | void>();
    onMounted(() => { cleanup.value = fn(); });
    onBeforeUnmount(() => cleanup.value?.());
  },
  onUnmount(fn) {
    onBeforeUnmount(fn);
  },
};
```

React 适配层实现：

```typescript
import { useEffect, useLayoutEffect, useRef } from 'react';

const reactLifecycleAdapter: LifecycleAdapter = {
  onPreEffect: useLayoutEffect,  // 绘制前
  onPostEffect: useEffect,       // 绘制后
  onMount(fn) {
    const cleanup = useRef<(() => void) | void>();
    useEffect(() => {
      cleanup.current = fn();
      return () => cleanup.current?.();
    }, []);
  },
  onUnmount(fn) {
    useEffect(() => fn, []);
  },
};
```

## 痛点四：第三方依赖冲突

### 问题描述

组件库依赖的第三方包版本与消费方项目版本冲突，导致运行时错误或重复打包。

### 常见冲突场景

| 冲突类型 | 场景 | 症状 |
|---------|------|------|
| Vue/React 版本冲突 | 组件库用 Vue 3.4，消费方用 Vue 3.2 | 运行时报错或行为不一致 |
| 工具库重复打包 | 组件库和消费方都依赖 lodash | 打包体积翻倍 |
| 日期库冲突 | 组件库用 dayjs，消费方用 moment | 两个日期库共存 |
| React 多实例 | 组件库打包了 React | Hooks 报错 "Invalid hook call" |

### 解决方案

#### 方案一：框架作为 peerDependencies

```json
// ✅ Vue/React 声明为 peerDependencies，不打包进产物
{
  "peerDependencies": {
    "vue": ">=3.2.0"
  },
  "devDependencies": {
    "vue": "^3.4.0"  // 开发时用最新版测试
  }
}
```

构建配置中 external 排除框架：

```typescript
// vite.config.ts
export default {
  build: {
    rollupOptions: {
      external: ['vue', 'react', 'react-dom'],
    },
  },
};
```

#### 方案二：工具函数自实现，不依赖第三方

```typescript
// ✅ 核心工具函数自己实现，不引入 lodash/dayjs
// @xui/shared/src/utils/

// 简单 debounce —— 不依赖 lodash
export function debounce<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): (...args: Parameters<T>) => void {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<T>) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// 简单日期格式化 —— 不依赖 dayjs
export function formatDate(
  date: Date | number,
  pattern = 'YYYY-MM-DD'
): string {
  const d = new Date(date);
  const map: Record<string, string> = {
    YYYY: String(d.getFullYear()),
    MM: String(d.getMonth() + 1).padStart(2, '0'),
    DD: String(d.getDate()).padStart(2, '0'),
    HH: String(d.getHours()).padStart(2, '0'),
    mm: String(d.getMinutes()).padStart(2, '0'),
    ss: String(d.getSeconds()).padStart(2, '0'),
  };
  return pattern.replace(/YYYY|MM|DD|HH|mm|ss/g, (match) => map[match]);
}
```

#### 方案三：React 多实例检测

```typescript
// React "Invalid hook call" 最常见原因：组件库打包了 React
```

#### 方案四：pnpm overrides 强制版本

```json

{
  "pnpm": {
```

## 痛点五：事件对象差异

### 问题描述

Vue 的原生事件对象是浏览器原生 `MouseEvent`，React 的事件对象是 `SyntheticEvent` 包装层，属性和行为有差异。

### 差异对照

| 属性/方法 | Vue (原生事件) | React (SyntheticEvent) |
|-----------|---------------|----------------------|
| `e.target` | 原生 DOM | 原生 DOM |
| `e.currentTarget` | 原生 DOM | 原生 DOM |
| `e.stopPropagation()` | 原生行为 | React 合成事件池 |
| `e.preventDefault()` | 原生行为 | 合成事件 |
| 事件池 | 无 | React 17 已移除事件池 |
| 事件冒泡 | 原生 DOM 冒泡 | React 17+ 绑定在 root |
| `e.nativeEvent` | 不存在 | 获取原生事件 |

### 解决方案

**核心层只接收原生事件对象，适配层负责转换**：

```typescript
// 核心层 —— 接收原生 MouseEvent
export function createButtonLogic(options: {
  onClick?: (e: MouseEvent) => void;
}) {
  function handleClick(nativeEvent: MouseEvent) {
    options.onClick?.(nativeEvent);
  }
  return { handleClick };
}
```

```tsx
// React 适配层 —— SyntheticEvent → nativeEvent
function Button({ onClick }) {
  const logic = createButtonLogic({ onClick });

  const handleReactClick = (e: React.MouseEvent) => {
    logic.handleClick(e.nativeEvent); // 转换为原生事件
  };

  return <button onClick={handleReactClick} />;
}
```

```vue
<!-- Vue 适配层 —— 直接传递原生事件 -->
<script setup>
const logic = createButtonLogic({ onClick: props.onClick });
const handleVueClick = (e: MouseEvent) => {
  logic.handleClick(e); // Vue 事件就是原生事件
};
</script>
<template>
  <button @click="handleVueClick" />
</template>
```

## 痛点六：ref / forwardRef 差异

### 问题描述

Vue 和 React 暴露组件内部方法/实例的机制不同。React 19 引入了 `ref-as-prop`，`forwardRef` 已废弃，导致 React 17/18/19 三代 API 差异。

| 机制 | Vue 3 | React 17/18 | React 19+ |
|------|-------|-------------|-----------|
| 暴露方式 | `defineExpose()` | `forwardRef` + `useImperativeHandle` | **ref 作为普通 prop** + `useImperativeHandle` |
| 获取方式 | `template ref` | `useRef` | `useRef`（无变化） |
| 类型 | 组件实例 | `RefObject<T>` | `RefObject<T>`（无变化） |
| forwardRef | 不适用 | 必须使用 | **已废弃，不再需要** |

### 解决方案

**核心层定义统一的 ref 接口**：

```typescript
// @xui/core/src/components/input/types.ts
export interface InputRef {
  focus: () => void;
  blur: () => void;
  select: () => void;
  getValue: () => string;
  setValue: (value: string) => void;
}
```

**Vue 适配层**：

```vue
<script setup lang="ts">
import type { InputRef } from '@xui/core/components/input';

const inputRef = ref<HTMLInputElement>();

// 暴露统一的 ref 接口
defineExpose<InputRef>({
  focus: () => inputRef.value?.focus(),
  blur: () => inputRef.value?.blur(),
  select: () => inputRef.value?.select(),
  getValue: () => inputRef.value?.value ?? '',
  setValue: (val: string) => {
    if (inputRef.value) inputRef.value.value = val;
  },
});
</script>
```

**React 19+ 适配层**（ref 作为普通 prop，无需 forwardRef）：

```tsx
import { useImperativeHandle, useRef } from 'react';
import type { InputRef } from '@xui/core/components/input';

export function Input({ ref, ...props }: InputProps & {
  ref?: React.Ref<InputRef>;
}) {
  const inputRef = useRef<HTMLInputElement>(null);

  useImperativeHandle(ref, (): InputRef => ({
    focus: () => inputRef.current?.focus(),
    blur: () => inputRef.current?.blur(),
    select: () => inputRef.current?.select(),
    getValue: () => inputRef.current?.value ?? '',
    setValue: (val: string) => {
      if (inputRef.current) inputRef.current.value = val;
    },
  }), []);

  return <input ref={inputRef} {...props} />;
}
```

**React 17/18 兼容适配层**（使用 forwardRef）：

```tsx
import { forwardRef, useImperativeHandle, useRef } from 'react';
import type { InputRef } from '@xui/core/components/input';

export const Input = forwardRef<InputRef, InputProps>(
  (props, ref) => {
    const inputRef = useRef<HTMLInputElement>(null);
    useImperativeHandle(ref, (): InputRef => ({
      // 同上实现
    }), []);
    return <input ref={inputRef} {...props} />;
  }
);
Input.displayName = 'Input';
```

## 痛点七：provide/inject vs Context

### 问题描述

Vue 的 `provide/inject` 和 React 的 `Context` 用于跨层级传递数据，但 API 和行为不同。

### 解决方案

**核心层定义 Provider 契约，双端各自实现**：

```typescript
// @xui/core/src/components/form/context.ts
export interface FormContextValue {
  values: Record<string, any>;
  errors: Record<string, string>;
  setFieldValue: (name: string, value: any) => void;
  validateField: (name: string) => Promise<void>;
  registerField: (name: string) => () => void;
}

// 提供给 Vue 和 React 各自实现 provide/inject 或 Context
export const FormContextKey = Symbol('FormContext') as InjectionKey<FormContextValue>;
```

**Vue 适配层**：

```typescript
// @xui/vue/src/components/form/use-form-context.ts
import { inject, provide } from 'vue';

export function provideFormContext(value: FormContextValue) {
  provide(FormContextKey, value);
}

export function useFormContext(): FormContextValue | undefined {
  return inject(FormContextKey, undefined);
}
```

**React 适配层**：

```typescript
// @xui/react/src/components/form/form-context.ts
import { createContext, useContext } from 'react';

export const FormContext = createContext<FormContextValue | undefined>(undefined);

export function useFormContext(): FormContextValue | undefined {
  return useContext(FormContext);
}
```

## 痛点八：SSR 差异

### 问题描述

Vue 和 React 的 SSR（服务端渲染）机制不同，组件需要同时兼容两种 SSR 方案。

### 解决方案

**核心层避免在初始化时访问 DOM/浏览器 API**：

```typescript
// ❌ 错误：模块顶层访问 window，SSR 时崩溃
const isClient = typeof window !== 'undefined';
const scrollbarWidth = isClient
  ? window.innerWidth - document.documentElement.clientWidth
  : 0;

// ✅ 正确：延迟到运行时获取
function getScrollbarWidth(): number {
  if (typeof window === 'undefined') return 0;
  return window.innerWidth - document.documentElement.clientWidth;
}
```

**React SSR 兼容**：

```typescript
// useSyncExternalStore 的第三个参数是 SSR 快照
const state = useSyncExternalStore(
  logic.subscribe,    // 客户端订阅
  logic.getState,     // 客户端快照
  logic.getState,      // SSR 快照（返回初始状态）
);
```

## 痛点速查表

| 痛点 | 核心原因 | 一句话解决 |
|------|---------|-----------|
| 响应式差异 | Vue Proxy vs React state | 核心层用观察者模式，适配层桥接 |
| 闭包陷阱 | React useState 闭包固定值 | 核心层自管理状态，不依赖闭包 |
| vDOM diff 差异 | 双端 diff 算法不同 | 核心层管理列表数据，双端只渲染 |
| key 不一致 | index 作 key 导致行为差异 | 统一用稳定 id 作 key |
| 生命周期时序 | watch 同步 vs useEffect 异步 | onPreEffect=useLayoutEffect, onPostEffect=useEffect |
| 事件对象 | SyntheticEvent vs 原生事件 | 核心层只接收原生事件，React 端 .nativeEvent 转换 |
| ref 暴露 | defineExpose vs forwardRef(17/18) vs ref-as-prop(19) | 核心层定义 ref 接口，React 19+ 用 ref prop，17/18 用 forwardRef |
| 依赖冲突 | 版本不匹配/重复打包 | peerDependencies + external + 工具自实现 |
| SSR 兼容 | window 未定义 | 延迟获取浏览器 API，useSyncExternalStore 三参数 |
| React 19 forwardRef 废弃 | React 19 ref 作为普通 prop | 双路径导出：19+ 用 ref prop，17/18 用 forwardRef |
| React Compiler 冲突 | 手动 memo 与 Compiler 冲突 | 适配层不手动 memo，让 Compiler 优化 |
| ref cleanup 函数 | React 19 新增 ref 回调清理 | ref 回调可返回清理函数，替代 useEffect cleanup |
