# 03 - 统一组件规范

## 概述

本章定义跨框架组件库的统一规范，确保 Vue 和 React 双端组件在 API 层面行为一致。所有规范在 `@xui-design/core` 抽象层以 TypeScript 类型定义与 `ComponentSpec` 运行时规格固化，并通过 CI 中的契约测试（`scripts/contract-test.ts`）自动校验双端实现是否对齐。

当前已落地组件：**Button / Input / Modal**。本章示例均取自这三个组件的真实契约；面向未来组件的约定会显式标注「约定（未来组件）」。

## 一、Props 约定

### 1.1 命名规范

| 规则 | 约定 | 真实示例 |
|------|------|------|
| 命名风格 | camelCase（TS 层）/ kebab-case（Vue 模板） | `maxLength` / `max-length` |
| 布尔属性 | 遵循原生语义直接命名，不加 `is-` 前缀 | `disabled` / `readonly` / `clearable` |
| 枚举值 | 小写字符串联合类型 | `type?: 'default' \| 'primary' \| 'danger' \| 'link'` |
| 回调属性 | 一律 `on` 前缀 + 驼峰 | `onInput` / `onClose` / `onMaskClick` 不作 prop |
| 尺寸类 | 使用 `sm / md / lg` 三档 | `size?: 'sm' \| 'md' \| 'lg'` |
| 受控/非受控 | 受控 `visible`/`value` + 非受控 `defaultVisible`/`defaultValue` | `visible?` 与 `defaultVisible?` |
| v-model 兼容 | Vue 端额外支持具名 v-model 语法糖 | `v-model:visible` = `:visible` + `@update:visible` |

**受控与非受控双模式**：同时提供 `value`/`visible`（受控，由外部驱动）与 `defaultValue`/`defaultVisible`（非受控，仅作初始值）。适配层判断受控值是否传入决定运行模式，这与原生 React 表单组件的惯例一致。

### 1.2 Props 类型定义模板（以 Modal 真实契约为例）

```typescript
// @xui-design/core/src/components/modal/types.ts

export type ModalProps = {
  // --- 可见性（受控 / 非受控二选一）---
  /** 受控可见性（变更时由适配层同步给逻辑层） */
  visible?: boolean;
  /** 非受控初始可见性 */
  defaultVisible?: boolean;

  // --- 内容与尺寸 ---
  /** 标题（也可被 title 插槽覆盖） */
  title?: string;
  /** 宽度（数字按 px，字符串原样输出），默认 520 */
  width?: number | string;

  // --- 行为 ---
  /** 是否显示右上角关闭按钮，默认 true */
  closable?: boolean;
  /** 点击遮罩是否关闭，默认 true */
  maskClosable?: boolean;
  /** 按 ESC 是否关闭，默认 true */
  closeOnEsc?: boolean;

  // --- 回调（均无载荷）---
  onOpen?: () => void;
  onClose?: () => void;
  /** 确认回调（触发后自动关闭） */
  onOk?: () => void;
  /** 取消回调（触发后自动关闭） */
  onCancel?: () => void;
};
```

默认值不在类型文件中单独导出，而是集中声明在该组件的 `ComponentSpec.props.defaults` 中：

```typescript
// @xui-design/core/src/components/modal/spec.ts（节选）
export const modalSpec = {
  name: 'Modal',
  props: {
    type: {
      visible: Boolean,
      defaultVisible: Boolean,
      title: String,
      width: [Number, String],
      closable: Boolean,
      maskClosable: Boolean,
      closeOnEsc: Boolean,
      onOpen: Function,
      onClose: Function,
      onOk: Function,
      onCancel: Function,
    },
    defaults: {
      width: 520,
      closable: true,
      maskClosable: true,
      closeOnEsc: true,
    },
  },
  // ...
} satisfies ComponentSpec<ModalProps, ModalEvents, ModalSlots, ModalLogic>;
```

### 1.3 Vue/React Props 传递对比

| 特性 | Vue 3 | React | 统一约定 |
|------|-------|-------|----------|
| 传递方式 | `:closable="true"` | `closable={true}` | 属性名相同，语法各用各的 |
| 布尔简写 | `<Modal closable />` | `<Modal closable />` | 双端一致支持 |
| 事件回调 | `@close="handler"` | `onClose={handler}` | Vue 用 `@` 语法糖，React 用 `on` 前缀 prop |
| v-model | `v-model:visible` | 不支持，需手写受控 | Vue 端额外提供具名 v-model 语法糖 |
| 默认值 | 响应式 Props 解构中写默认值 | 函数参数解构默认值 | 以 `@xui-design/core` 的 spec defaults 为准，双端对齐 |
| 必填校验 | `defineProps<T>()`（TS 检查）| TS 检查 | 统一用 TypeScript 强约束 |

### 1.4 v-model 双端统一方案（以 Input 真实契约为例）

```typescript
// @xui-design/core/src/components/input/types.ts（节选）
export type InputProps = {
  /** 受控值（提供时进入受控模式） */
  value?: string;
  /** 非受控初始值 */
  defaultValue?: string;
  /** 每次键入回调 */
  onInput?: (value: string) => void;
  /** 值变更提交回调（失焦或回车） */
  onChange?: (value: string) => void;
  // ...其余 props
};
```

**Vue 端** —— 使用 `defineModel('value')` 支持具名 v-model：

```vue
<script setup lang="ts">
// <XInput v-model:value="name" />
// 等价于 :value + @update:value
const modelValue = defineModel<string>('value', { default: '' });
</script>
```

**React 端** —— 标准受控写法：

```tsx
<XInput value={name} onInput={setName} />
```

双端内部走的是同一个 `createInputLogic` 核心逻辑；v-model 仅是 Vue 侧的语法糖，契约层不感知。Modal 同理：Vue 端 `v-model:visible`，React 端 `visible` + `onClose` 受控。

## 二、事件处理机制

### 2.1 事件命名规范

| 事件类别 | 命名规则 | 真实示例 |
|---------|----------|------|
| DOM 事件 | 事件名 → React prop `on` 首字母大写 | `click` → `onClick`；`focus` → `onFocus` |
| 语义回调事件 | 动词 → `on` 首字母大写 | `onInput` / `onClose` / `onOk` / `onCancel` |
| 清空类事件 | 动词 → `on` 首字母大写 | `onClear` |

约定（未来组件）：如需表达「某状态发生变化」的事件，使用 `on` + 名词 + `Change`（如 `onValueChange`）；动画结束事件使用 `onAfter` + 动作（如 `onAfterOpen`）。当前三个组件未使用此类事件。

### 2.2 事件载荷规范

载荷不强制统一为对象，按信息量从简：

| 场景 | 载荷形式 | 真实示例 |
|------|---------|------|
| DOM 原生事件 | 原生事件对象（核心层只接收原生事件） | `click: (event: MouseEvent) => void`；`focus: (event: FocusEvent) => void` |
| 只需一个值 | 直接传值（不包对象） | Input 的 `input: (value: string) => void` |
| 无需信息 | 无载荷 | Modal 的 `open` / `close` / `ok` / `cancel` |
| 包含多个字段（约定·未来组件） | 对象载荷，字段含义内聚 | `onSelect: (payload: { value: string; label: string }) => void` |

原则：当事件需要携带两个及以上字段、或未来可能扩展时，使用对象载荷；单值或无值时保持简单，避免无意义的包装层。

### 2.3 Vue/React 事件映射

以 Modal 的 `close`（无载荷）和 Input 的 `input`（字符串载荷）为例：

```
契约事件                Vue 适配层                        React 适配层
┌──────────────┐   ┌───────────────────────┐   ┌──────────────────────┐
│ close        │──>│ emit('close')         │──>│ onClose?: () => void │
├──────────────┤   ├───────────────────────┤   ├──────────────────────┤
│ input(value) │──>│ emit('input', value)  │──>│ onInput?: (value:    ││
│              │   │                       │   │   string) => void    │
└──────────────┘   └───────────────────────┘   └──────────────────────┘
Vue 使用: @close / @input        React 使用: onClose={} / onInput={}
```

Vue 的 `defineEmits` 使用元组类型形式（如 `{ close: []; input: [value: string] }`），与 `@xui-design/core` 中的事件类型保持结构一致。

### 2.4 事件冒泡策略

| 策略 | 说明 | 真实示例 |
|------|------|------|
| 内部处理后透传 | 组件内部处理状态，再 emit 给父组件 | Button 点击 → 核心层处理 loading/disabled → `click` |
| 行为触发自动收尾 | 语义动作完成后按约定关闭弹窗 | Modal `ok`/`cancel` 触发后自动关闭，同时 emit 事件 |
| 拦截阻止 | 内部容器事件不向外冒泡 | 弹窗遮罩/面板点击不触发外部 document 级处理 |

## 三、插槽 / Children 映射规则

### 3.1 当前组件插槽映射总表

| 组件 | 抽象层 Slot | Vue 适配层 | React 适配层 |
|------|------------|-----------|-------------|
| Button | `default` / `icon` / `loadingIcon` | `<slot>` / `<slot name="icon">` / `<slot name="loadingIcon">` | `children` / `renderIcon` / `renderLoadingIcon` |
| Input | `prefix` / `suffix` / `clearIcon` | `<slot name="prefix">` 等 | `renderPrefix` / `renderSuffix` / `renderClearIcon` |
| Modal | `default` / `title` / `footer` | `<slot>` / `<slot name="title">` / `<slot name="footer">` | `children` / `renderTitle` / `renderFooter` |

### 3.2 映射规则详解

#### 默认插槽

```vue
<!-- Vue：Button.vue -->
<span class="xui-button__content">
  <slot />
</span>
```

```tsx
// React：Button.tsx
<span className="xui-button__content">{children}</span>
```

#### 具名插槽

具名插槽 `xxx` 在 React 侧统一映射为 `renderXxx` 回调 prop。以 Modal 真实契约为例（注意是 `title` 插槽、`renderTitle` 回调，`title` 插槽覆盖 `title` prop）：

```typescript
// @xui-design/core ModalSlots
export type ModalSlots = {
  default: Record<string, never>;
  /** 标题（覆盖 title prop） */
  title: Record<string, never>;
  /** 底部操作区 */
  footer: Record<string, never>;
};
```

```tsx
// React ModalComponentProps（节选）
export type ModalComponentProps = ModalProps & {
  children?: ReactNode;
  renderTitle?: () => ReactNode;
  renderFooter?: () => ReactNode;
  ref?: Ref<ModalRef>;
};

// 使用：
<Modal renderTitle={() => <h3>自定义标题</h3>} renderFooter={() => <FooterActions />} />
```

Input 的 `prefix` / `suffix` / `clearIcon` 同理映射为 `renderPrefix` / `renderSuffix` / `renderClearIcon`。

#### 作用域插槽（约定·未来组件，当前未使用）

当前三个组件的插槽均无作用域参数。未来组件如需作用域插槽，约定如下：

- Vue：`<slot name="item" v-bind="slotProps" />`，消费侧 `#item="slotProps"`
- React：映射为接收参数的回调 prop，`renderItem?: (slotProps: T) => ReactNode`

### 3.3 命名映射约定

```
Vue slot name          →    React prop name
────────────────────────────────────────────
default                →    children
icon                   →    renderIcon
loadingIcon            →    renderLoadingIcon
prefix                 →    renderPrefix
suffix                 →    renderSuffix
clearIcon              →    renderClearIcon
title                  →    renderTitle
footer                 →    renderFooter
```

**规则：具名插槽 `xxx` → React `renderXxx`；作用域插槽 `xxx`（未来）→ React `renderXxx(params)`**

## 四、生命周期对应关系

### 4.1 生命周期映射总表

| 抽象层阶段 | Vue 3 | React | 触发时机 |
|-----------|-------|-------|---------|
| 挂载前 | `onBeforeMount` | (无直接等价) | DOM 插入前 |
| 挂载后 | `onMounted` | `useEffect(() => {}, [])` | DOM 插入后 |
| 更新前 | `onBeforeUpdate` | (无直接等价) | 更新 DOM 前 |
| 更新后 | `onUpdated` | `useEffect`（无空依赖数组） | 更新 DOM 后 |
| 绘制前布局操作 | `watch(..., { flush: 'pre' })` | `useLayoutEffect` | 浏览器绘制前 |
| 卸载前 | `onBeforeUnmount` | `useEffect` cleanup | DOM 移除前 |
| 卸载后 | `onUnmounted` | (无直接等价) | DOM 移除后 |

### 4.2 实际桥接方式（不引入额外生命周期抽象）

组件库不提供独立的生命周期抽象层——适配层直接使用各自框架的生命周期原语完成两件事：**订阅清理**与 **Props 同步**。

#### Vue 适配层

```vue
<script setup lang="ts">
import { onUnmounted, ref, watchEffect } from 'vue';

// 核心层状态 → Vue 响应式
const state = ref(logic.getState());
const unsubscribe = logic.subscribe((next) => {
  state.value = next;
});

// Props 变更 → 核心层
watchEffect(() => {
  logic.updateOptions({ disabled, loading });
});

// 卸载时取消订阅
onUnmounted(() => {
  unsubscribe();
});
</script>
```

#### React 适配层

```tsx
import { useEffect } from 'react';

// Props 变更 → 核心层（effect 的 cleanup 机制天然覆盖卸载场景）
useEffect(() => {
  logic.updateOptions({ disabled, loading });
}, [logic, disabled, loading]);

// 订阅由 useSyncExternalStore（useLogicState）管理，无需手动 cleanup
```

需要在浏览器绘制前操作 DOM（如自动聚焦）时：Vue 使用 `watch`（默认 `flush: 'pre'`），React 使用 `useLayoutEffect`；绘制后执行测量等操作：Vue 使用 `watch(..., { flush: 'post' })` 或 `onUpdated`，React 使用 `useEffect`。

## 五、样式隔离方案

### 5.1 方案选型对比

| 方案 | Vue SFC `<style scoped>` | CSS Modules | 全局 BEM 样式表（实际采用） | Shadow DOM |
|------|:-:|:-:|:-:|:-:|
| Vue 原生支持 | ✅ 原生 | ✅ 需配置 | ✅ | ✅ |
| React 原生支持 | ❌ | ✅ 需配置 | ✅ | ✅ |
| 双端统一 | ❌ 各写各的 | ✅ | ✅（共用同一套类名） | ✅ |
| 运行时开销 | 0 | 0 | 0 | 0 |
| SSR 兼容 | ✅ | ✅ | ✅ | 差 |
| 类名可读性 | `xui-btn__text` | `_xui-btn__text_1a2b` | `xui-button__content` | 原始 |
| DevTools 调试 | 好 | 一般 | 好 | 差(Shadow) |

### 5.2 实际方案：全局 BEM 样式表 + CSS 变量

双端组件使用**同一套全局 BEM 类名**，组件样式**单一来源**于 `@xui-design/styles`：

```
packages/styles/src/
├── reset.scss                   # 基础重置 + 主题 token（:root CSS 变量）
├── components.scss              # 组件样式（button / input / modal 全量 BEM）
└── index.scss                   # @use 上述两者，构建输出 dist/index.css

packages/vue/src/
└── components/button/Button.vue  # SFC 内保留非 scoped 的 <style> 块（单组件场景）

packages/react/src/
└── components/button/Button.tsx  # 通过 className 引用 BEM 类名
```

- 组件样式只在 `@xui-design/styles/src/components.scss` 维护一份；`@xui-design/vue` / `@xui-design/react` 的 dist **不再各自携带组件 CSS**，消费方导入 `@xui-design/styles`（开发）或 `@xui-design/styles/index.css`（产物）一次即可
- Vue SFC 内的非 scoped `<style>` 与 `components.scss` 保持内容一致（双通道：单组件引入 vs 整包引入）
- 双端类名、结构、token 降级值逐行一致，杜绝视觉漂移

> 演进记录：早期采用「vue/react 各持一份 components.css」的重复方案，两份文件漂移导致过双端主题/尺寸不一致缺陷（见 docs/09），已中心化收敛。

#### BEM 命名规范

```scss
.xui-button {                  // Block
  display: inline-flex;

  &--primary { /* ... */ }     // Modifier：类型 / 尺寸
  &--sm { /* ... */ }

  &__icon { /* ... */ }        // Element
  &__content { /* ... */ }

  &.is-disabled { /* ... */ }  // State：is- 前缀
  &.is-loading { /* ... */ }
}
```

- 类型/尺寸修饰类：`xui-button--primary`、`xui-button--sm`
- 状态类统一 `is-` 前缀：`is-disabled`、`is-loading`、`is-block`、`is-focused`、`is-readonly`

### 5.3 CSS 变量主题系统

主题 token 由 `@xui-design/styles` 提供，定义在 `packages/styles/src/reset.scss` 的 `:root` 中（`index.scss` 通过 `@use` 引入）：

```scss
:root {
  // 颜色
  --xui-color-primary: #4f46e5;
  --xui-color-primary-hover: #4338ca;
  --xui-color-primary-active: #3730a3;
  --xui-color-text: #1f2937;
  --xui-color-text-secondary: #6b7280;
  --xui-color-border: #d1d5db;
  --xui-color-bg: #fff;
  --xui-color-bg-disabled: #f3f4f6;

  // 圆角
  --xui-radius-sm: 4px;
  --xui-radius-md: 6px;
  --xui-radius-lg: 8px;

  // 字体
  --xui-font-size-sm: 12px;
  --xui-font-size-md: 14px;
  --xui-font-size-lg: 16px;

  // 间距
  --xui-spacing-xs: 4px;
  --xui-spacing-sm: 8px;
  --xui-spacing-md: 12px;
  --xui-spacing-lg: 16px;
}
```

组件样式引用这些变量时提供降级值（如 `var(--xui-radius-md, 6px)`），保证未引入 `@xui-design/styles` 时组件仍可渲染。用户覆盖主题只需重定义 CSS 变量：

```css
/* 深色主题示例 */
.dark-theme {
  --xui-color-text: rgba(255, 255, 255, 0.85);
  --xui-color-bg: #1a1a1a;
  --xui-color-border: #374151;
}
```

### 5.4 全局样式与重置

`packages/styles/src/reset.scss` 同时承担基础重置与 token 定义：

```scss
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

:root {
  // ...同 5.3 的主题 token
}
```

由消费方应用在入口处引入一次（`@xui-design/styles`），组件库本身不强制注入重置样式。

## 六、图标规范（@xui-design/icons）

组件内置图标（Modal 关闭、Input 清除、Button loading 等）**统一取自 `@xui-design/icons`**，不在适配层内各自维护 SVG 路径。

### 6.1 API

```ts
import { icons, getIconSvg, createIconElement, ICON_NAMES } from '@xui-design/icons';
import type { IconName } from '@xui-design/icons';

icons.close;                                  // 内层 SVG 标记（不含 <svg> 壳）
getIconSvg('close', { size: 16 });            // 完整 <svg> 字符串（SSR / 文档）
createIconElement('close', { size: 14 });     // DOM SVGSVGElement（浏览器）
```

当前基础图标集（10 个）：`close / clear / loading / check / search / plus / minus / arrow-up / arrow-down / calendar`。

### 6.2 SVG 壳约定

所有图标统一：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`（颜色随文本）、`stroke-width="2"`、`stroke-linecap/linejoin="round"`。个别图标（如 loading 的粗线段、dasharray）在**内层标记**上覆写。

### 6.3 适配层集成方式

- Vue：`<svg ... v-html="icons.close" />`
- React：`<svg ... dangerouslySetInnerHTML={{ __html: icons.close }} />`

保留组件原有的 BEM 类名与 DOM 结构（如 `.xui-button__spinner`、`.xui-modal__close`），仅内部路径数据来自 icons 包，确保样式与测试不受影响。新增图标：先在 `packages/icons/src/index.ts` 扩充 `icons` 映射与 `IconName`，再在组件中引用。

## 规范检查清单

每个新增组件 PR 必须通过以下检查：

- [ ] Props 类型在 `@xui-design/core` 统一定义，默认值声明在对应 spec 的 `defaults` 中，Vue/React 适配层引用同一契约
- [ ] 回调 prop 遵循 `on` 前缀 + 驼峰命名
- [ ] 事件载荷按信息量从简（原生事件 / 单值 / 无载荷），多字段时使用对象载荷
- [ ] 受控 `value`/`visible` 与非受控 `defaultValue`/`defaultVisible` 双模式齐备
- [ ] 具名插槽映射为 React 的 `renderXxx` 回调；作用域插槽映射为带参回调
