## Phase 0：基础设施搭建

### 步骤 1：Monorepo 初始化

#### 任务

搭建 pnpm workspace + Turborepo 的 Monorepo 基础结构。

#### 执行动作

```bash
# 1. 初始化根项目
mkdir cross-framework-ui && cd cross-framework-ui
pnpm init

# 2. 配置 workspace
cat > pnpm-workspace.yaml << 'EOF'
packages:
  - "packages/*"
  - "apps/*"
EOF

# 3. 安装核心工具
pnpm add -Dw turbo typescript@5.4 @changesets/cli prettier eslint
pnpm add -Dw husky lint-staged

# 4. 创建包目录
mkdir -p packages/{shared,core,vue,react,styles,icons,utils}
mkdir -p apps/{playground-vue,playground-react,docs}

# 5. 初始化 Changesets
pnpm changeset init

# 6. 初始化 Git Hooks
pnpm husky init
echo "pnpm lint-staged" > .husky/pre-commit
```

#### 交付物

| 交付物 | 路径 | 说明 |
|--------|------|------|
| 根 package.json | `/package.json` | 含 turbo 脚本 |
| workspace 配置 | `/pnpm-workspace.yaml` | 包路径声明 |
| Turbo 配置 | `/turbo.json` | 任务编排 |
| 基础 TS 配置 | `/tsconfig.base.json` | 共享 TS 配置 |
| 各包骨架目录 | `/packages/*` | 空的包结构 |

#### 验收标准

- [ ] `pnpm install` 无错误
- [ ] `pnpm -r exec -- echo ok` 遍历所有包成功
- [ ] 各包 `package.json` 的 name 字段已声明（`@xui-design/shared` 等）

### 步骤 5：核心逻辑实现

#### 任务

在 `@xui-design/shared` 中实现每个组件的纯逻辑核心（状态管理 + 交互逻辑 + 校验逻辑）。

#### 执行动作

为每个组件创建逻辑工厂函数：

```typescript
// packages/shared/src/components/<name>/use-<name>-logic.ts
export function create<Name>Logic(options: <Name>Props) {
  // 1. 内部状态（闭包变量，不依赖框架）
  // 2. 状态订阅机制（Set<listener>）
  // 3. 交互方法（handleClick, handleChange 等）
  // 4. 配置更新方法（updateOptions）
  // 5. 返回 { subscribe, getState, ...methods, updateOptions }
}
```

#### 交付物

| 交付物 | 路径 |
|--------|------|
| 逻辑工厂 | `packages/shared/src/components/*/use-*-logic.ts` |
| 通用 hooks | `packages/shared/src/hooks/*.ts` |
| 工具函数 | `packages/shared/src/utils/*.ts` |
| 统一导出 | `packages/shared/src/index.ts` |

#### 核心逻辑实现检查清单

每个 `createXxxLogic` 工厂函数必须满足：

- [ ] 零框架导入（不出现 `import ... from 'vue'` 或 `react`）
- [ ] 使用闭包管理状态，通过 `subscribe` 通知变更
- [ ] `getState()` 返回不可变快照（浅拷贝）
- [ ] `updateOptions()` 支持外部更新配置
- [ ] 所有方法返回值为 `void` 或 `Promise<void>`（不直接返回 DOM/框架对象）

#### 验收标准

- [ ] `@xui-design/shared` 可在 Node.js 环境直接 import 运行（无需 jsdom）
- [ ] 每个 `createXxxLogic` 可独立实例化并测试
- [ ] `pnpm test --filter @xui-design/shared` 全部通过

## Phase 2：双端适配开发

### 步骤 7：Vue 适配层

#### 任务

在 `@xui-design/vue` 中为每个组件实现 Vue SFC 版本，调用核心层逻辑。

#### 执行动作

每个组件创建：

```
packages/vue/src/components/<name>/
├── <name>.vue          ← Vue SFC（<script setup> + <template> + <style>）
├── use-<name>.ts       ← Vue 适配 hook（桥接核心层 → Vue ref）
└── index.ts            ← 导出
```

#### Vue 适配层实现模板

每个 `.vue` 文件遵循统一结构：

```vue
<script setup lang="ts">
// 1. 引入核心层逻辑和类型
import { createXxxLogic } from '@xui-design/shared';
import type { XxxProps } from '@xui-design/core/components/xxx';

// 2. defineProps + defineEmits + defineSlots
const props = withDefaults(defineProps<XxxProps>(), { ... });
const emit = defineEmits<{ ... }>();

// 3. 创建核心逻辑实例
const logic = createXxxLogic(props);

// 4. 状态桥接：核心层 → Vue ref
const state = ref(logic.getState());
logic.subscribe((next) => { state.value = next; });

// 5. Props 变更同步
watchEffect(() => { logic.updateOptions(props); });

// 6. 事件处理
function handleClick(e: MouseEvent) {
  logic.handleClick(e);
  emit('click', e);
}
</script>

<template>
  <!-- 渲染模板，使用 state + props -->
</template>
```

#### 交付物

| 交付物 | 路径 |
|--------|------|
| Vue 组件 | `packages/vue/src/components/*/<name>.vue` |
| 适配 hooks | `packages/vue/src/components/*/use-<name>.ts` |
| 统一导出 | `packages/vue/src/index.ts`（含 Vue 插件 install） |

#### 验收标准

- [ ] 每个 Vue 组件可被 `import { Xxx } from '@xui-design/vue'` 正确引入
- [ ] Props / Events / Slots 与 `@xui-design/core` 契约完全对齐
- [ ] 组件在 `apps/playground-vue` 中可渲染且交互正常
- [ ] `pnpm type-check --filter @xui-design/vue` 通过
- [ ] Vue 组件测试覆盖率 ≥ 80%

### 步骤 8：React 适配层

#### 任务

在 `@xui-design/react` 中为每个组件实现 React 版本，调用核心层逻辑。

#### 执行动作

每个组件创建：

```
packages/react/src/components/<name>/
├── <name>.tsx          ← React 19+ 组件（ref-as-prop + JSX）
├── <name>-legacy.tsx   ← React 17/18 兼容（forwardRef 版本）
├── use-<name>.ts       ← React 适配 hook（桥接核心层 → useSyncExternalStore）
└── index.ts            ← 导出（运行时版本检测选择路径）
```

#### React 适配层实现模板

React 19+ 主版本（ref 作为普通 prop，无需 forwardRef）：

```tsx
import { useImperativeHandle, useEffect } from 'react';
import { useSyncExternalStore } from '../../hooks/use-sync-external-store';
import { createXxxLogic } from '@xui-design/shared';
import type { XxxProps } from '@xui-design/core/components/xxx';

export function Xxx({ ref, ...props }: XxxComponentProps & {
  ref?: React.Ref<XxxRef>;
}) {
  // 1. 创建核心逻辑实例
  const logic = createXxxLogic(props);

  // 2. Props 变更同步
  useEffect(() => {
    logic.updateOptions(props);
  }, [props.disabled, props.loading]);

  // 3. 状态桥接：useSyncExternalStore
  const state = useSyncExternalStore(
    logic.subscribe,
    logic.getState,
    logic.getState
  );

  // 4. ref 暴露（React 19 中 ref 是普通 prop）
  useImperativeHandle(ref, () => ({ ... }), []);

  // 5. 事件处理
  const handleClick = (e: React.MouseEvent) => {
    logic.handleClick(e.nativeEvent);
    props.onClick?.(e.nativeEvent);
  };

  // 6. 渲染 JSX
  return ( /* ... */ );
}
```

React 17/18 兼容版本使用 `forwardRef` 包装，逻辑同上。`index.ts` 运行时检测 React 版本选择导出路径。

| 适配 hooks | `packages/react/src/components/*/use-<name>.ts` |
| 统一导出 | `packages/react/src/index.ts` |

### 步骤 12：持续迭代机制

#### 任务

建立组件库的持续迭代流程，确保后续新增组件、修复 Bug 时有标准流程。

#### 执行动作

#### 新增组件标准流程

**第一步（推荐）：脚手架一键生成骨架**

```bash
# 自动在四层生成可编译、可测试的骨架（契约 / 逻辑 / 双端适配 / 测试）
# 并自动注册各包导出与样式占位；生成物立即可通过 lint / type-check / test
pnpm exec tsx scripts/create-component.ts <Name>
```

脚手架产出（以 `Select` 为例）：

| 层 | 生成文件 |
|----|---------|
| @xui-design/core | `src/components/select/{types.ts, spec.ts, index.ts}`（Props/Events/Slots/State 契约 + ComponentSpec） |
| @xui-design/shared | `src/components/select/create-select-logic.ts`（闭包状态 + subscribe 逻辑工厂）+ `__tests__/` |
| @xui-design/vue | `src/components/select/Select.vue`（defineProps + emit + 订阅清理）+ `index.ts` + `__tests__/` |
| @xui-design/react | `src/components/select/Select.tsx`（useSyncExternalStore + 回调 latest-ref）+ `index.ts` + `__tests__/` |
| 注册 | core/shared/src/index.ts、vue/react/src/index.ts 导出追加；styles components.scss 样式占位 |

**第二步：按 TODO 注释实现业务**（各生成文件内标注参照文件：Vue 参照 Modal.vue 的受控/命令式模式、React 参照 Modal.tsx 的 ref + latest-ref 模式、样式参照 components.scss 既有段落）。

**第三步：更新契约测试矩阵** —— `scripts/contract-test.ts` 中将新组件加入双端 Props/事件/默认值对齐检查。

**第四步：全套检查与提交**

```bash
# 全套检查
pnpm lint && pnpm type-check && pnpm test && pnpm build --force
pnpm exec tsx scripts/contract-test.ts
pnpm exec tsx scripts/check-bundle-size.ts

# 创建 changeset 并提交 PR
pnpm changeset
git checkout -b feat/<new-component>
git add . && git commit -m "feat: add <NewComponent> component"
git push -u origin feat/<new-component>
# 创建 PR → CI 通过 → 合并 → 发布
```

| 交付物 | 路径 |
